NuMaker-IoT-MA35D16FJ87C OpenBMC Quickstart & Reference

Operational guide for building, flashing, and verifying OpenBMC on the Nuvoton NuMaker-IoT-MA35D16FJ87C evaluation board. The board acts as an out-of-band BMC controlling an external host via Redfish, WebUI, Serial-Over-LAN (SOL), and GPIO power signals (POWER_OUT, RESET_OUT, PS_PWROK).

1. Hardware Specifications

Item Detail
Board NuMaker-IoT-MA35D16FJ87C
SoC Nuvoton MA35D16FJ87C (Dual Cortex-A35 @ 800 MHz)
RAM 512 MB DDR3L (stacked in MCP)
Storage Support SPI NAND (512MB), Raw NAND (NFI), MicroSD / SD (SDHCI1)
Debug Console UART0 (/dev/ttyS0), 115200 8N1
Host SOL Console UART10 (/dev/ttyS10), Pins PH6 (RX) / PH7 (TX)
RS-485 Interface UART12 (/dev/ttyS12), Pins PC13 (AUD / nRTS), PC14 (RXD), PC15 (TXD)
CAN Bus 3× Bosch M_CAN: CAN0 (PN2/PN3), CAN1 (PN6/PN7), CAN3 (PM2/PM3)
Power Control GPIO: POWER_OUT (PN1), RESET_OUT (PN0), PS_PWROK (PK12)
Network 10/100M / 10/100/1000M Ethernet (RMII / RGMII)
Default IP / mDNS DHCP or numaker-iot-ma35d16fj87c.local
Default Credentials root / 0penBmc

2. Build Environment & Compilation

Note

All build commands below are executed inside the Docker container. If you have not set up the Docker build environment yet, please refer to Docker Build Environment Guide to build and enter the container first.

Ensure at least 60 GB of free disk space for toolchain builds and sstate cache.

2.1 Build Steps

  1. Inside the Docker container, switch to the OpenBMC repository:
cd ~/openbmc
  1. Initialize the build directory:
MACHINE=numaker-iot-ma35d16fj87c source setup numaker-iot-ma35d16fj87c build-ma35
  1. Start compilation:
bitbake nuwriter-pack
Note

For subsequent sessions in a new shell:

cd ~/openbmc

source oe-init-build-env build-ma35

bitbake nuwriter-pack

2.3 Prebuilt Artifacts from GitHub Actions

Precompiled zip packages are available from the CI pipeline:

  1. Go to: OpenBMC GitHub Actions Workflow.
  2. Sign in to your GitHub account (required to download Actions artifacts) and select the latest successful build.
  3. Download openbmc-numaker-iot-ma35d16fj87c.zip from Artifacts and extract it on Windows.

4.2 Network & Access

  • mDNS Hostname Resolution:

    ping -c 3 numaker-iot-ma35d16fj87c.local

    (If mDNS is blocked on your router, log into UART0 and check ip addr show eth0).

  • SSH Access:

    ssh root@numaker-iot-ma35d16fj87c.local
# Password: 0penBmc

  • WebUI Browser Access: Navigate to https://numaker-iot-ma35d16fj87c.local/ (or https://<BMC-IP>/). Accept the default self-signed SSL certificate in your browser and log in with root / 0penBmc.

5.2 Host Serial-Over-LAN (SOL) Console

On numaker-iot-ma35d16fj87c, UART10 (/dev/ttyS10, PH6/PH7) is assigned as the Host SOL link.

  1. Interactive CLI Access via SSH (Direct):
    ssh -t root@numaker-iot-ma35d16fj87c.local obmc-console-client
    Connects directly to the serial console server regardless of host power state.
  2. WebUI Terminal: Open Operations → Serial-over-LAN console.
    Note

    WebUI terminal checks host power status (PS_PWROK on PK12). If evaluating standalone without a host motherboard, tie PK12 to 3.3V and set Host Power to On via Redfish, or use direct CLI access via obmc-console-client.

Refer to Serial-Over-LAN (SOL) Console Guide for loopback tests and wiring details.

5.3 Independent RS-485 Interface (Hardware AUD)

On numaker-iot-ma35d16fj87c, UART12 (/dev/ttyS12, PC13~PC15) provides hardware Auto-Direction (AUD) control.

  1. Configure baudrate:
    stty -F /dev/ttyS12 115200 cs8 -cstopb -parenb -echo
  2. Transmit test packet:
    echo "RS-485 AUD Test Packet" > /dev/ttyS12
  3. Receive test packet:
    cat /dev/ttyS12

Refer to RS-485 Serial Interface Guide for hardware AUD principles and pin connections.

5.4 CAN / CAN-FD Bus

MA35D16FJ87C provides 3 CAN controllers: can0 (PN2/PN3), can1 (PN6/PN7), can2 (PM2/PM3).

Warning

SoC CAN pins output 3.3V TTL levels. Connect via an external 3.3V CAN transceiver (e.g. SN65HVD230 / TJA1051T) with 120Ω termination resistors on both bus ends. Do NOT connect TTL pins directly to a 12V/24V CAN bus.

Configure can0 and can1 for CAN-FD in BMC SSH:

ip link set can0 type can bitrate 500000 dbitrate 2000000 fd on

ip link set can0 up

ip link set can1 type can bitrate 500000 dbitrate 2000000 fd on

ip link set can1 up

Receiver:

candump can1

Transmitter:

cansend can0 123##3112233445566778899AABBCCDDEEFF

See CAN / CAN-FD Guide for transceiver pin connections and packet formats.

5.5 Host Power Control (GPIO)

Signal Direction Pin Description
POWER_OUT Output PN1 Emulates power button (Active Low, 200ms on, 4s force off)
RESET_OUT Output PN0 Emulates reset button (Active Low, 200ms)
PS_PWROK Input PK12 Host PSU Power Good status (Active High 3.3V) 
# Power On Host:
curl -k -s -u root:0penBmc -X POST \
  https://numaker-iot-ma35d16fj87c.local/redfish/v1/Systems/system/Actions/ComputerSystem.Reset \
  -H "Content-Type: application/json" \
  -d '{"ResetType": "On"}' -i
# Expected: HTTP/1.1 204 No Content

See GPIO Power Control Guide for GPIO timing and control guides.

5.6 SoC Temperature Monitoring

Via D-Bus (on BMC):

busctl get-property xyz.openbmc_project.MA35_Thermal /xyz/openbmc_project/sensors/temperature/cpu_thermal xyz.openbmc_project.Sensor.Value Value

Via Redfish:

curl -k -s -u root:0penBmc https://numaker-iot-ma35d16fj87c.local/redfish/v1/Chassis/system/ThermalSubsystem/ThermalMetrics | jq .

Stress and polling test script:

./test-cpu-temp.sh

5.7 Firmware Update via Redfish (OTA)

End-to-end Redfish update with dual-bank (A/B) flashing and boot fallback:

# Automated end-to-end OTA verification (from repo root):
./meta-numaker/doc/numaker-iot-ma35d16fj87c/test-redfish-update/test-redfish-update.sh numaker-iot-ma35d16fj87c.local \
  build-ma35/tmp/deploy/images/numaker-iot-ma35d16fj87c/obmc-phosphor-image-numaker-iot-ma35d16fj87c.mtd-ubi-tar

For partition architecture, manual step-by-step curl commands, anti-rollback checks, and boot fallback testing, refer to Redfish Firmware Update (OTA) Guide.
